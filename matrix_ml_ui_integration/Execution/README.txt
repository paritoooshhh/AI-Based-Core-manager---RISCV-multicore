MATRIX MULTIPLICATION + CORE-COUNT DEMO (V1)

Files:
- matrix_core_demo.v: self-contained Verilog simulation testbench/model.
- run_matrix_demo.ps1: compile then run a 4x4 showcase.
- predict_and_run.py: demonstrates a small scikit-learn DecisionTreeClassifier trained on synthetic labels from the declared cycle model; compares 1/2/4 core candidates.

Run in PowerShell:
  Set-ExecutionPolicy -Scope Process Bypass
  .\run_matrix_demo.ps1

Try other sizes:
  python .\predict_and_run.py 2
  python .\predict_and_run.py 4
  python .\predict_and_run.py 8
  python .\predict_and_run.py 16

IMPORTANT CLAIM LIMIT:
This is a self-contained demonstration model, not integrated with the user's RISC-V datapath.
The Verilog models row-partitioned parallel multiply-accumulate work. It computes a golden result and checks all output elements.
The cycle model counts one multiply-accumulate as one modeled cycle, adds 8 modeled coordination cycles per additional core, and reports the maximum worker cycles plus coordination overhead.
The Python DecisionTreeClassifier is trained on synthetic labels generated by the same declared cycle model, NOT the previously trained project model. Do not claim independent generalization or real ML superiority.
For a truthful submission, describe this as a matrix multiplication scheduling prototype unless it is integrated with the trained model and real CPU RTL.


DESKTOP UI
Run: python .\matrix_scheduler_ui.py
The UI recompiles the standalone Verilog model, runs model inference and 1/2/4-core candidates, then displays prediction, cycle comparisons, correctness, matrix output, and full run log. It still uses the synthetic-label decision tree in predict_and_run.py, not the project's earlier saved model or original RISC-V CPU datapath.
